# 回填（query-filed）

将本次对话中产生的有价值内容沉淀为 wiki 页面——即 CLAUDE.md query 工作流第 4 步——并完成全部簿记同步。本技能假定 CLAUDE.md schema 在场（在本仓库内执行）。

## 输入

`$ARGUMENTS` 可指定回填范围（如"上一轮"、"关于 X 的讨论"）；为空时默认覆盖本会话中**尚未回填**的有价值问答。

## 步骤

1. **盘点**：梳理会话中未回填的有价值内容；先读 [[wiki/index]] 核对哪些已落库，避免重复建页。涉及多轮时先向用户列清单确认；仅一两轮则直接执行、事后汇报。
2. **归类**（优先更新既有页面，其次新建）：
   - 跨来源的通用概念 / 机制 → `wiki/concepts/<slug>.md`
   - 具体人物 / 组织 / 产品 / 工具 → `wiki/entities/<slug>.md`
   - 用户提供了新 raw 来源 → 转 ingest 工作流，不用本技能
3. **写入**：遵循 CLAUDE.md 页面模板（frontmatter：type / created / updated / sources）；更新既有页面必须 bump `updated`；中文正文、英文 slug（小写 + 连字符）；wikilink 用 `[[wiki/路径|别名]]`；**AI 推断标注"待来源验证"**；无法溯源到 raw/ 的外部事实在"依据来源"小节内联链接并声明"待剪藏"，同时登记"后续线索"。
4. **交叉引用**：grep 新页面标题/关键词，为提及它的既有页面反向补链，修复明显的缺失交叉引用。
5. **同步（缺一不可，铁律 2）**：
   - `wiki/index.md`：对应分节加一行 `[[wikilink]] — 一句话摘要`；
   - `wiki/log.md`：追加 `## [YYYY-MM-DD] query-filed | 标题`，列出新建/更新页面与关键决策。
6. **汇报**：向用户列出变更清单（新建/更新/同步的文件），提示待剪藏项；产生新 lint 线索时一并说明。

## 边界

- 铁律 1：绝不写 `raw/`。
- 铁律 5：不静默回退用户手改；与既有页面内容冲突时保留用户内容并标记。
- 铁律 7：矛盾不裁决，只标记并提醒用户。
- 内容单薄（一句话可说清）不建新页，并入既有页面。
- git commit 仅在用户明确要求时执行。
