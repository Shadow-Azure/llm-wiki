Current context

先用一个例子说清为什么需要 Data Agent

假设算法工程师问：“找一批高铁场景掉线样本，要覆盖晚高峰，还要能追溯来源。”过去这个问题会在群聊、表名搜索、临时 SQL 和手工抽检里反复消耗时间。

1人问“高铁掉线样本在哪里？口径是什么？”
2Agent 理解识别场景=高铁、时间=晚高峰、事件=掉线、输出=训练样本。
3混合检索关键词、向量、业务图谱和规则一起找到场景资产。
4治理执行校验权限、质量、成本；生成分区裁剪 SQL 或 Spark 作业。
5给出证据返回数据、口径、行数、血缘、风险和可复用任务。

第一层：湖仓数据

原始层保留日志与报文，主题层形成小区、事件、配置和指标，样本层沉淀特征与标签快照，集市层输出场景数据产品。

第二层：发布数据集

对象存储中的 Parquet/CSV 不能只是“文件包”，要带 Manifest、Schema、采样规则、质量报告、血缘认证和授权信息。

第三层：Data Agent

LLM 翻译意图、选择工具、解释结果；SQL、Spark、画像、血缘、质量和权限检查由确定性工具完成。

Reference architecture

总体参考架构：一个湖仓，一个控制面，一类 Agent 入口

关键不是把大模型接到数据库上，而是把目录、语义、血缘、质量、权限和执行工具组装成受治理的任务系统。

Pain point 01

如何在庞大湖仓里按场景和自然语言找到并高效使用数据

数据不再缺，缺的是“可信入口”。找到表只是开始，还要知道口径、权限、成本、质量、分区和推荐用法。

01

资产发现：从表名搜索到场景资产检索

业务语言、技术表名和执行计划之间需要语义层连接。Data Agent 应该优先消费高可信、有 Owner、有 SLA 的场景资产。

痛点

基站日志横跨网元、小区、用户、事件、指标、配置、时间、地理和厂商。只靠表名搜索回答不了：“高铁场景掉线样本在哪里？”“哪些数据能支撑干扰优化模型？”“这个指标和现网 KPI 是否同一口径？”找到表后，还要判断分区、扫描量、权限、成本、质量和下游用法。

Pain point 02

如何快速分析发布数据集的成分、特征分布、上下游关系和质量

发布数据集不应是对象存储里的黑盒文件包，而应自带“数据护照”：来自哪里、包含什么、规则是否变化、适合什么任务、风险在哪里。

02

数据集体检：一键生成数据护照

用业务切片看成分，用条件分布看特征，用列级血缘看上下游，用七维指标看质量，最后由 Agent 给出处置建议。

痛点

对象存储中的发布数据集常常只有路径和训练效果。使用者不知道样本来自哪些小区、时间、场景和厂商，也不知道特征是否泄漏、类别是否失衡、上下游规则是否变化、质量是否满足目标模型。人工检查 Schema 和抽样脚本慢，结果也不可复现。

Pain point 03

如何对比仿真采集与现网采集数据的差异

仿真数据可控、标签充足；现网数据真实但有偏差。重点不是看两张全局直方图像不像，而是看同场景、同负载、同事件下机制是否一致，任务是否可迁移。

03

Sim-to-Real：从统计对比到任务迁移

先统一实体、时间粒度和事件口径，再做场景匹配、分布对比、机制对比和跨域训练评测，最后输出可迁移、需重加权、需补数据三类结论。

痛点

仿真数据可能缺少真实噪声、异常网元、用户行为、邻区干扰和测量误差；现网数据存在采样偏差、口径不一致、配置差异和长尾场景稀疏。直接混合训练会引入 sim-to-real 差距；直接看均值又可能掩盖条件分布和因果机制差异。

业界洞察
业界案例架构与技术方案对本项目的启示
Waymo Simulation / Safety Hub用真实驾驶日志重建场景、生成挑战场景、做闭环仿真，并用安全指标评估模拟与实路差异。构造可复现场景集，比较安全/异常事件的条件分布和模型失败模式，不只看全局均值。

Applied Intuition / 自动驾驶数据闭环通用实践场景挖掘、合成数据生成、域随机化、真实边缘案例补齐、模型回归评测。用现网长尾事件反哺仿真场景库，用仿真增强稀缺异常，再用真实集做最终验证。
Keysight / Ansys / MATLAB 5G Toolbox 等通信仿真工具链从链路级、系统级、射频/信道到网元行为建模，支持可控实验与协议一致性验证。把仿真物理参数映射进业务本体，否则仿真指标无法与现网 KPI 精准对齐。
MLOps 漂移监测通用实践PSI、K-S、Jensen-Shannon、Wasserstein、MMD、adversarial validation、模型性能跨域评估。分布指标必须与任务指标绑定；只报统计差异不足以说明能否迁移。
合成数据评测实践评价 fidelity、privacy、utility、coverage，重点看下游模型增益和失败样本覆盖率。给仿真数据独立评分卡：保真度、覆盖度、隐私/合规、下游增益、条件稳定性。
启示
先统一本体，再比较数值统一小区、载波、时间窗、事件定义、测量粒度、单位、空值语义、过滤规则和异常定义。口径不同，统计差异都会失真。
做场景匹配，不做全网平均构建相同城市类型、地形、负载、频段、拓扑、用户分布和事件类型的匹配对，避免 Simpson's paradox。
分布差异分层报告单变量用 PSI、K-S、Jensen-Shannon、Wasserstein；多变量用协方差差异、MMD、adversarial validation；还要看时间/空间自相关和热点漂移。
机制差异比直方图更重要比较负载升高时 PRB、调度失败、切换失败是否相似；干扰增强时 SINR、MCS、吞吐量是否保持相似因果方向和时延。
任务效用是最终裁判做仿真训练→现网测试、现网训练→仿真测试、混合训练→真实测试、预训练+微调→真实测试，观察准确率、召回、校准和长尾失败。
让差异驱动闭环发现高负载干扰事件缺失后，自动生成仿真参数建议、补充采集工单或合成样本需求，并把新数据集登记回场景库。

Roadmap

落地路线：不要一步追求“全自动”

先把资产和口径讲清楚，再开放问答；先把数据护照补齐，再让 Agent 自动生成样本作业；最后才让差异分析驱动采集和仿真。

L1
资产可见表、列、文件、指标、场景、Owner、权限可搜索统一目录、语义标签、血缘、基础质量报告。
L2
问答可用自然语言定位数据并解释口径混合检索、场景语义模型、SQL/Spark dry-run、成本预估。
L3
产品可信发布数据集自带契约和质量分Manifest、数据护照、质量门禁、列级血缘、版本快照。
L4
加工自动业务问题生成参数化样本作业场景模板、特征契约、负样本策略、训练集生成与评测。
L5
闭环优化缺口驱动采集、仿真和建模场景缺口、Sim-to-Real 报告、重加权与样本增强建议。

先做的 30 天清单

1

选 3 个高价值场景高铁掉线、干扰优化、切换异常。不要一开始索引全网所有表。

2

写清场景资产卡业务问题、KPI 口径、源表、时间窗、样本规则、负样本、Owner、已知限制。

3

打通最小血缘源 Iceberg 快照 → Spark 作业 → 对象存储 Manifest。

4

给 10 个必检规则缺失率、KPI 范围、时间连续性、标签泄漏、正负比、重复度等。

需要守住的边界

✓

自然语言问答无线 KPI、厂商私有字段和口径复杂，必须有语义层约束和人工确认。

✓

自动画像缺失率、分布和相关性能发现异常，但不能自动解释所有异常，需领域规则复核。

✓

仿真评估统计保真度、覆盖度、隐私和下游增益可能冲突，应按训练目标加权。

✓

双通道打通对象文件必须反查 Iceberg 快照、Spark 作业和源表版本，否则血缘断链。
