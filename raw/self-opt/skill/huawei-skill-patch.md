# 华为云三段式 Skill 自进化

> 一句话：华为云 Agent 技术体系（以 OfficeClaw 应用为例）用"任务反思引擎（从成功轨迹与用户修正中沉淀 skill 原型，补丁式精准更新 SKILL.md）→ 进化工厂（低负载窗口内按失败率优先级做反思式定向变异）→ 评估管道（准入/沙箱/多维目标三层把关，'不差于原版且至少一维严格更优'才保留，允许多样性变体并存）"三段闭环，让 skill 从真实办公行为中自动生长；个人技能库按用户隔离，团队技能库脱敏泛化后共享。

## 是什么 / 背景

来源为华为云技术社区"技术栈"（jishuzhan.net）文章 [《让Skill从执行中生长：Cloud Agent Harness的三段式Skill自进化机制》](https://jishuzhan.net/article/2055237085632237570)，作者 Leonardo Li、Rain Zhang、Jian Huang（页面未标注发布日期，accessed 2026-08-26）。

文章开篇给出动机：Agent 能力边界取决于 skill 质量与数量，人工维护很快遇到瓶颈——"业务场景变化比文档更新快，操作者发现的技巧很难被系统化沉淀，大量有价值但低频的操作经验最终流失在日志里"。同时指出自进化的工程风险：轨迹混杂试错分支，"自动提炼的时候很容易把噪声当成经验"；迭代几轮后可能停滞甚至退化，"每一步都需要仔细设计校验和兜底机制"。

文章先综述了三种技术流派，再介绍华为云融合三派的三段式机制（这段流派综述本身是很好的产业图谱索引）：

1. **轨迹蒸馏**（从历史轨迹提炼 skill）：代表 Hermes Agent（任务成功时调 Skill_manage 工具生成标准 SKILL.md，"并通过补丁机制精准更新Skill的失效描述"）、GenericAgent（复旦，<3.3K 行核心代码）、SkillX（规划/功能/原子三层抽象）。
2. **进化迭代**（变异-评估-选择）：Hermes Agent 引入 GEPA 把 prompt 作进化个体 + Pareto 选择；EvoSkill 以 skill 文件夹为进化单元、仅失败时触发变异；HyperAgents 进化对象扩展至 Agent 全部代码；Harness Evolution Loop 外层元进化。
3. **评估驱动的工程优化**（skill 当可测试软件模块）：DSPy；Anthropic Skill Creator 2.0（"提供可视化评估界面，自动重写触发描述并盲测比较输出质量"）。

## 机制：用户数据怎么流动

（全部引文出自 [原文](https://jishuzhan.net/article/2055237085632237570)）

**信号来源（显式 + 隐式）**
- 任务成功完成的完整执行轨迹（异步序列化）："本次任务的全部执行数据——包括用户的原始请求、Agent 的每步工具调用及其输入输出、分支决策、出现的错误及修复过程、以及用户手动介入的节点"。
- 用户的手动修正（隐式信号）：任务反思引擎"监听复杂任务的成功完成及用户的手动修正"。
- 团队空间 skill 的近期执行日志（尤其失败日志）——供进化工厂消费。

**分析方式**
- 第一段·任务反思引擎：驻留 Agent 运行时，"当任务复杂度或用户干预超过阈值时"，调用 LLM 分析完整轨迹，压缩为结构化 Skill 文档，"仅保留使任务成功所必需的步骤，丢弃那些被废弃的试错分支"。
- 第二段·进化工厂：在"系统预定的低负载窗口内"批量执行，三步走——
  - **选取**（失败率优先级）："失败率偏高的 Skill 优先进入队列，长期未被调用但仍有订阅者的 Skill 次之，表现稳定的 Skill 排在最后。"
  - **变异**（反思式定向变异）：输入是该 skill 近期所有执行的失败日志（而非单次成功轨迹）；进化 Agent 分析失败原因（触发条件过窄、特定条件下步骤失效、参数建议值不合理等），"为每个失败模式生成针对性的修改方案"；变异体数量按调用频率和失败次数动态决定，每个变异体在保持原意下调整措辞、步骤顺序或参数建议。
  - **筛选**：全部变异体送评估管道。

**生成什么改进**
- 新 skill 文件（从成功轨迹提炼）或对现有 SKILL.md 的**补丁式精准更新**："若该任务涉及用户对已有 Skill 的修正，引擎不会重写整个文件，而是精准修改 Skill 中对应的段落。这种补丁机制既保留了原始经验的价值，又避免了全文重写带来的计算开销。"

**评估把关（第三段·评估管道，三层）**
- **准入检查**：格式校验（符合标准文档结构、不含幻觉出的工具调用）、安全扫描（不会建议越权和危险操作）、最小功能测试（简化用例上可被正确加载执行）。
- **沙箱效果评估**：通过者在沙箱运行完整测试用例（创建时自动合成的正常/边缘/少量对抗场景 + 历史执行日志采样的高价值回归用例）；每个变异体独立上下文执行，"系统记录其准确率、执行延迟、Token 消耗和安全合规评分"。
- **多维目标筛选**："一个变异体被保留的基本条件是它在多维度上的综合表现不差于原始 Skill，且至少在一个维度上严格优于原始 Skill。"且为维持多样性，"系统不会只保留唯一的最优版本，而是允许在某个特定维度上有显著优势的变体同时存在，为下一轮进化提供样本。"

**谁审批 / 怎么上线 / 共享边界**
- 审批："一个可选的步骤是用户可配置是否人工审核进化后的 Skill 以保证进化的确定性"（即人工审核为可配置项，非默认强制）。
- 上线：新 skill 先进个人技能库，"供其后续同类任务时直接调用"；个人工作空间 skill "实时生效并随用户迁移"。
- 隔离与共享："个人技能库中的 Skill 不会自动共享到其他用户或团队，除非用户主动将 Skill 上传至 Skill-hub"；"团队空间中的 Skill 经脱敏和泛化后可被组织内其他成员订阅"。进化工厂只对团队空间 skill 执行变异筛选。
- 回滚：文章未描述显式回滚机制（评估管道的保留条件是防退化主手段）——此为数据缺口。
