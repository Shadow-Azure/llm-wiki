Case 01 · Skill Packaging

Anthropic Agent Skills

Anthropic 把 Agent 能力组织成带说明、资源、脚本和示例的 Skill 包，并通过渐进式披露控制上下文负担。它解决的不是“再想一个神奇 prompt”，而是专家经验如何资产化。

关键词：Skill 包渐进式披露可复用流程脚本与门禁
01

它想解决什么问题

在没有 Skill 包机制时，团队通常把所有经验塞进一个系统提示词。短期看似有效，但很快会出现四类问题。

问题 1

上下文越来越胖

审计规范、代码风格、测试流程、领域知识、输出格式全部常驻上下文。真正与当前任务相关的部分反而被稀释，模型容易忽略关键约束。

问题 2

经验不可复用

某个人调好的财务报表 prompt、数据分析流程或文档模板常在聊天记录里。换项目、换模型、换同事后，这些经验难以迁移。

问题 3

能力边界不清

系统不知道什么时候该用某段提示词，也不知道它需要哪些输入、会调用哪些工具、失败时如何降级。

问题 4

不能稳定执行

模型可以用自然语言描述“先检查数据，再生成图表”，但如果每一步都靠模型即兴写代码，格式、公式和输出路径仍然容易漂移。

一句话理解：Agent Skills 把“专家 SOP”从聊天记录升级为工程资产：有名字、有描述、有正文、有资源、有脚本、有适用范围。
02

它是怎么解决的

Agent Skills 的核心机制可以概括为：文件化 Skill + 精简元数据 + 按需加载正文 + 可执行资源。

四个关键设计

设计通俗解释解决什么
SKILL.mdSkill 的说明书，包含用途、触发条件、步骤和注意事项。把隐性经验显性化。
精简描述运行时先只看名字和简介，不读全文。避免所有 Skill 常驻上下文。
资源文件模板、参考文档、数据 schema、示例输出。减少把所有知识写进正文。
脚本工具固定计算、校验、转换和报告生成逻辑。提高可重复性，降低模型漂移。
03

示例：生成月度 SaaS 留存报告

假设团队经常要基于订单、续费和退款数据生成留存报告。以前每人写一遍 prompt，口径经常不同。现在做一个 saas-retention-report Skill。

第 1 步：Agent 看到索引

用户只说“帮我生成上月 SaaS 留存报告”。运行时先看到 Skill 简介：“处理订阅续费、净收入留存和留存图表，输入为标准 CSV，输出为 HTML/PDF 报告。”

第 2 步：判断命中并加载正文

任务与描述匹配，Agent 加载 SKILL.md，看到必须使用统一口径：留存以付费账户为单位；退款不扣除当期新增；异常账户要单独标注。

第 3 步：校验输入

Skill 里的 validate_input.py 检查必填列、日期格式、币种、重复订单和负数金额。发现 refund_at 有 3 条空值，脚本返回结构化错误。

第 4 步：执行固定计算

Agent 调用 calculate_retention.py，脚本按月份 cohort 计算 gross retention 和 net revenue retention，并输出中间 CSV。

第 5 步：渲染报告

Agent 使用 report-template.html 填充标题、口径说明、图表、异常行和结论。不是每次让模型即兴决定报告结构。

第 6 步：自动校验和交付

validate_report.py 检查图表数据与中间 CSV一致、所有口径解释存在、异常表非空。最后 Agent 给出文件路径和三句话总结。

效果：模型不再负责“记住所有公式”，而是负责理解任务、选择 Skill、解释异常和串联工具。公式、口径和格式由 Skill 资产保证。
04

实际会遇到的问题与处理方式

阶段可能问题典型表现解决方法
Skill 选择命中错误 Skill普通数据问答触发了复杂留存报告。描述中写清“何时用/何时不用”，加入负例和路由条件。
上下文正文仍然过长关键约束被稀释，模型忽略口径。拆成入口卡 + 分章节资源，只加载当前需要的部分。
输入数据 schema 漂移列名变了、日期格式混杂、金额单位不一致。先执行 schema 校验，失败时要求补齐或降级为澄清问题。
计算模型即兴写公式同一数据每次算出不同留存率。把公式和聚合逻辑放入脚本，模型只处理解释和异常。
资源模板与正文冲突正文说 A 口径，模板注释说 B 口径。Skill 做版本化 review，测试资源和正文的一致性。
安全脚本权限过大示例脚本能访问网络或删除文件。最小权限、只读目录、白名单输出路径和依赖锁。
演进一次重写全量 Skill原本能用的流程突然大面积失败。小步变更、保留旧版本、跑回归任务集。
常见误区：Skill 包不是“把 20,000 token 说明书换个目录保存”。如果入口没有精简索引、正文没有模块化、关键动作没有脚本化，它只是把上下文膨胀换了个文件名。
05

对 SDD Harness 的启示

启示 1

Skill 是资产

每个 Skill 应该有版本、负责人、适用边界、失败模式和回归集。

启示 2

入口要轻

运行时先看摘要，不要把所有流程一次塞进模型上下文。

启示 3

确定步骤下沉

公式、校验、格式和危险动作交给脚本、模板和门禁。

落地模板：SKILL.md 写触发条件和核心流程；references/ 放领域知识；scripts/ 放校验和转换；tests/ 放最小回归；CHANGELOG.md 记录每个版本的行为变化。
