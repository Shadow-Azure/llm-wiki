Case 05 · Lifelong Learning Agent

Voyager

Voyager 是一个在 Minecraft 中持续学习的 LLM Agent。它不是按固定任务清单执行，而是根据当前状态自动提出课程，把成功探索写成可执行技能代码，存入技能库，并在后续任务中检索复用。

关键词：自动课程技能库环境反馈迭代提示终身学习
01

它想解决什么问题

开放世界 Agent 有三个难点：任务没有固定顺序，奖励稀疏，成功经验很容易用完就丢。传统 Agent 常常能做一步动作，却不能把经验变成明天还能用的能力。

问题 1

探索无方向

世界里能做的事太多，Agent 不知道下一步该学什么。

问题 2

技能不复用

每次都从零写代码或重新推理，已经学会“合成木板”也不能稳定复用。

问题 3

反馈太稀疏

只告诉 Agent“最终胜利/失败”不够，它需要每一步的可执行反馈。

问题 4

长程依赖强

做钻石镐需要木头、工作台、木镐、石镐、熔炉等多个前置技能。

问题 5

失败难以定位

可能是代码错、状态错、资源不足、坐标错，也可能是前置条件没满足。

问题 6

静态任务会过期

环境状态变化后，旧计划失效，Agent 需要根据新状态重选目标。

02

它是怎么解决的

Voyager 的答案可以概括为：自动课程 + 可执行技能库 + 环境反馈迭代 + 语义检索复用。

四个核心组件

组件作用类比
自动课程根据当前状态选择合适难度的下一个目标。教练看学员现状，安排“先练运球”，而不是直接打职业赛。
技能库保存成功技能的代码、描述和使用条件。把“怎么换轮胎”写成手册，下次按目录调用。
迭代提示失败后带着报错和状态重新修改技能。跑代码看报错，修一行再跑。
语义检索新任务来了，找到相关旧技能。搜索“怎么获得石头”，找到“用木镐采石”。
关键差异：Voyager 存的是“程序化技能”，不是纯自然语言总结。代码可以被反复执行，环境结果能证明它是否有效。
03

示例：从零学会制造石镐

这个任务有明确依赖链：树 -> 木板 -> 工作台 -> 木镐 -> 石头 -> 石镐。它很适合展示 Voyager 如何拆课程、修错误、存技能。

第 1 步：读取状态

Agent 看到：空手、无物品、附近有树。技能库里还没有相关技能。

第 2 步：自动课程生成目标

课程器不直接提“挖钻石”，而是提出“采集木头”，因为这是当前状态下最合理的前置任务。

第 3 步：生成技能代码

Agent 写一个 collect_wood()：找到最近树、移动、攻击树干、检查背包中木头数量。

第 4 步：环境反馈修正

第一次执行失败：只攻击了树叶，没得到木头。环境返回背包数量为 0。Agent 修改为攻击原木并循环直到数量达标。

第 5 步：入库

成功后保存 collect_wood，描述为“靠近树并采集至少 N 个原木”，同时保存使用条件和返回值。

第 6 步：检索并组合

下一个目标是“制作工作台”。Agent 检索到 collect_wood，调用它保证有原木，再生成 craft_planks() 和 craft_crafting_table()。

第 7 步：前置技能复用

要制作木镐时，Agent 检索到木板和工作台技能，组合出流程：确保木板足够 -> 靠近工作台 -> 合成木镐。

第 8 步：处理新失败

采石头失败，因为没有石镐或距离不对。环境反馈显示工具不匹配。课程器改为先完成木镐，再采石，最后保存 mine_stone() 和 craft_stone_pickaxe()。

效果：Agent 不但完成了石镐，还沉淀了木头、木板、工作台、木镐、采石等技能。下次做熔炉或铁镐时，可以检索并复用这些前置技能。
04

实际会遇到的问题与处理方式

阶段问题表现解决方法
课程目标太难Agent 反复失败，学不到东西。根据状态、资源和历史成功率调整课程。
课程目标太简单大量重复低价值任务。跳过已掌握技能，引入新组合和更高层目标。
技能生成代码语法错API 名称错、参数错、缩进错。返回解析器和运行时错误，迭代修复。
技能执行前置条件缺失没有木板就想做工作台。技能声明 precondition，执行前检查状态。
环境反馈反馈太模糊只报“失败”，不知道原因。记录物品变化、位置、报错和自检结果。
技能库重复技能堆积多个采集木头技能质量不一。按语义和功能去重，保留成功率高的版本。
技能库过期技能环境或 API 变化后不可用。定期执行验证，失败则标记为 deprecated。
安全危险动作无限移动、破坏地形、死循环。步数/时间/资源上限和沙箱执行。
迁移到工程 Agent 的坑：不要把一次性通过但脆弱的脚本直接当 Skill。工程 Skill 必须声明输入、前置条件、失败模式、清理动作和回归测试，否则技能库会变成垃圾场。
05

对 SDD Harness 的启示

启示 1

失败也是课程

bad case 可以用来生成下一个最小练习任务，而不是只做归档。

启示 2

技能要可执行

能被脚本、模板、门禁固化的经验，不要只写成自然语言。

启示 3

状态决定课程

Harness 应根据仓库、模块、历史失败和工具能力推荐下一步，而不是用固定大任务压垮 Agent。

映射关系：Minecraft 物品状态对应仓库/测试状态；技能代码对应 Skill 脚本与流程；自动课程对应从失败簇生成练习任务；环境反馈对应编译、测试、lint 和 review。
